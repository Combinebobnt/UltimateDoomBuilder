Baking lightmaps

Menu path: Tools -> Bake Lightmaps...
Action: "Bake Lightmaps" (Tools category). It has no default key; you can bind one in Preferences -> Controls.

This runs the ZDRay lightmap baker on the open map. ZDRay ray-traces the static light things placed in the map and writes a LIGHTMAP lump, together with its own node build (ZNODES) and a renumbered TEXTMAP, because the lightmap indexes into exactly those nodes. The editor keeps that result and writes it when you save or test the map, for as long as the map still matches what was baked.

Only UZDoom reads the LIGHTMAP lump, and only when it is started with the -enablelightmaps parameter.

Requirements

  • Game configuration: one of the UZDoom UDMF configurations (Doom, Heretic or Hexen). In other configurations the menu item is hidden.
  • Map format: UDMF.
  • A ZDRay executable. The editor does not include one. Build or download ZDRay and select it in the bake window.

Placing lights

The baker only reads the things in the Lightmap Lights category, which the UZDoom UDMF configurations provide. UZDoom does not spawn these things when the map runs: their light exists only in the bake.

Thing Type Settings
Lightmap Point Light 9876 Arguments 1 to 3 are red, green and blue (0 to 255), argument 4 is the radius. The thing's alpha sets the intensity and its height places the light vertically. The custom field light_softshadowradius gives the light a source size in map units for soft shadow edges (0, hard shadows, when absent). Keep it below the light's distance to the nearest wall, floor or ceiling, or that surface blocks part of the light. Upstream ZDRay ignores it.
Lightmap Spotlight 9881 Argument 1 is the color as hex text (for example ff8800), argument 2 the inner angle, argument 3 the outer angle, argument 4 the radius. Aim it with the thing's angle and pitch. It takes light_softshadowradius as the point light does.
ZDRayInfo 9890 Place one per map. Its custom fields: lm_suncolor (sun color as hex text, for example ffcc88), lm_sunintensity (sun brightness multiplier, 1.0 when absent, 0 to 16; upstream ZDRay ignores it and bakes at 1.0), lm_sampledistance (default sample distance in map units, 8 to 128, rounded to a power of two), lm_gridsize (light probe grid spacing, 32 when absent), lm_bounce (light bounces for indirect light, 0 when absent, 0 to 8; each bounce adds a lot of bake time, one bounce can make a bake ten or more times longer; upstream ZDRay ignores it, and it has only been checked with CPU ray tracing only on, while the baker uses its GPU tracer when it finds one), lm_ao (ambient occlusion, on unless set to false; it darkens corners and creases of the baked light only, the sector light is unchanged; a map without the field gains it when rebaked; upstream ZDRay ignores the field: its GPU tracer always bakes ambient occlusion and its CPU tracer never does), lm_skyintensity (sky light, soft fill light from all the sky a surface can see, so outdoor walls facing away from the sun are not black; 0 when absent, which is off, 0 to 16; the baked light adds to the sector light, so start around 0.5 and lower the outdoor sectors' light level; a map with sky light always bakes on the CPU), lm_skycolor (sky light color as hex text, ffffff when absent) and lm_skysamples (sky rays per texel, 256 when absent, 16 to 1024; more is smoother and slower). Upstream ZDRay ignores the three sky fields. Its angle and pitch set the sun direction.

Per-surface detail is set in the custom fields of each edit window:

  • Sidedefs: lm_sampledist, lm_sampledist_top, lm_sampledist_mid, lm_sampledist_bot.
  • Sectors: lm_sampledist_floor, lm_sampledist_ceiling.

A smaller sample distance gives finer shadows, but uses more lightmap texture space and makes the bake take longer.

Surface lights

A sidedef or a sector's floor or ceiling can glow and light the surfaces near it (lava, light panels, windows). Set them in the custom fields:

  • Sidedefs: lm_lightcolor (color picker), lm_lightintensity, lm_lightdistance. They cover the side's upper, middle and lower walls. On a two-sided line only the side that has them glows.
  • Sectors: lm_lightcolorfloor, lm_lightintensityfloor, lm_lightdistancefloor, and the same three for the ceiling.

The distance is how far the light reaches in map units; the surface stays unlit while it is 0, the default. The intensity is 0 to 16: 1 is faint, about 4 to 16 reads clearly. The light fades to nothing at the distance, and surfaces in the same plane as the glowing one (the floor around a lava pool, the wall beside a light panel) get none of it. On a 3D floor, the top glows with the control sector's ceiling fields and the bottom with its floor fields. Only ZDRay builds that support surface lights read these fields; upstream ZDRay ignores them.

Emissive textures (EMITDEFS)

Instead of setting fields on every surface, a mod can list the textures and flats that glow wherever they are used, in a text file named EMITDEFS: emitdefs.txt in the root of a PK3 or directory resource, or an EMITDEFS lump in any loaded WAD, the map's own WAD included. Each line is a texture name followed by keyword and value pairs: 

// comment
LAVA1                 color ff6020  intensity 1.0  distance 192  on flats
"textures/panel.png"  color auto    intensity 1.5  distance 128  on walls
  • color: six hex digits, default ffffff. auto uses the image's average color, scaled so its brightest channel is full; the intensity sets the brightness.
  • intensity (default 1, at most 16) and distance (required, in map units) mean the same as the surface light fields above, so a line and the fields with the same numbers give the same light.
  • on flats, on walls or on both (the default). Walls are the solid wall parts using the texture: the middle of a one-sided line and the upper and lower parts of a two-sided one.

A name matches however the map refers to the image: a long name, its short name or a path. Every frame of the texture's ANIMATED or ANIMDEFS animation glows with the same values, and a line for a frame of its own wins. Resources merge in load order: a later line for the same image and kind replaces an earlier one, and a line with intensity 0 removes it. Surface light fields on a side or sector win over the table for that surface. Two-sided middle textures, 3D floor sides and sky never glow. An unknown keyword is ignored and a line with a bad value is skipped, each with a warning in the Errors and Warnings window.

The bake's status line adds "Emissive textures: N entries, M used by this map." Only ZDRay builds that support emissive textures accept the table; with upstream ZDRay the bake fails and says so. Editing EMITDEFS and reloading resources makes an earlier bake out of date, like a map change does.

Things to know about the baker:

  • Sunlight only reaches surfaces that can trace a ray to a sky surface.
  • Ordinary dynamic lights (the Dynamic Lights category) are not baked.
  • UZDoom's lm_dynamic field is not read by ZDRay, so the editor does not offer it.

Baking

  1. Choose Tools -> Bake Lightmaps...
  2. The first time, set the ZDRay executable on the Run tab (use Browse...). Bake and Quick bake stay disabled until the file exists and the game configuration and map qualify; the status line says why.
  3. Set the options on the tabs below.
  4. Click Bake, or Quick bake for a fast low-resolution look. The window switches to the Output tab and shows the current stage, a progress bar, the elapsed seconds and the baker's last output lines. Cancel (or Escape) stops the baker and leaves the map exactly as it was, including its unsaved changes state.
  5. On success the status line reads "Baked in N s: ... Save or Test to use it." and the map is marked as changed. A bake that lights nothing fails with "the bake lit no surfaces (does the map have static light things or surface lights?)".

Baking never writes to the map file. The result is kept until the map is saved or tested.

The dialog's tabs

The editor asks the ZDRay executable which of the forked build's features it has when the window opens and whenever the path changes. An option the configured baker can't use stays visible but disabled, marked "needs ZDRay fork", and its tooltip names the feature; with upstream ZDRay every bake runs at the Final quality.

  • Lighting edits the map's ZDRayInfo thing (see above): sun on or off, sun colour and intensity, sun angle and elevation (degrees above the horizon, stored as the thing's angle and pitch), default sample distance, light probe grid size, light bounces, ambient occlusion and sky light colour and intensity, plus a read-only list of the EMITDEFS entries and whether the map uses each. Changes go to the map when you click Apply, Bake or Quick bake, as one undo step named "Edit lightmap lighting"; closing the window with changes not yet applied asks first. A value equal to the field's default removes the field, as the thing's own properties do. When the map has no ZDRayInfo thing the tab shows the baker's defaults, and applying a change adds one at the map's centre facing the default sun (angle 214, elevation 59); its first bake differs slightly from a bake without the thing. With several ZDRayInfo things the last one is used and edited. Turning the sun off needs a ZDRay build with the sunintensity feature; upstream ZDRay always bakes a sun.
  • Quality is kept per map, in its .dbs file; a map without its own setting uses the last values set in this dialog, and gets its own from its first change or Bake on. Quality preset: Draft, Normal or Final (the baker's own defaults) set the Sample distance scale (a multiplier on every sample distance, so 4 is four times coarser), Shadow samples and Bounce samples; changing one of these makes it Custom. Bounce samples only change anything once the baker bounces light. The presets need a ZDRay build with the samples feature. Sky samples is the map's lm_skysamples field, written with the Lighting values. Lightmap texture size: 128 to 4096, default 1024, the size of each lightmap texture page. Sizes above 1024 need a ZDRay build with size4096: other builds bake at 1024, and the status line says so. (Before the forked build gained that feature, 2048 and 4096 silently baked at 1024.)
  • Run holds the settings of this computer, kept for every map: the ZDRay executable, Threads (0 = automatic) (automatic uses the number of processor cores, at most 4) and CPU ray tracing only, which tells the baker to skip its Vulkan GPU tracer. The GPU tracer ignores the shadow and bounce sample counts and bakes at its own.
  • Output shows the baker's output lines of the running or last bake.

Quick bake bakes at the Draft quality with texture pages of at most 512, without changing the map's quality setting. Its result is a normal bake that Save and Test use.

What keeps a bake valid

The editor takes a fingerprint of the map when it bakes. Every Save, Save As, Save Into and Test Map compares the current map with that fingerprint:

  • Match: the baker's TEXTMAP (with your current things), ZNODES and LIGHTMAP are written, and the normal nodebuilder is skipped.
  • No match: the lightmap is left out and the normal nodebuilder runs. The next save into a file adds "Lightmap dropped: the map changed since it was baked." to the Errors and Warnings window, once. Autosaves drop the lightmap without a warning; Test Map warns (see below).

The fingerprint covers the map's geometry, sectors, sides and lines, and only the things the baker reads: the lightmap light things and probes, the ZDRayInfo sun, polyobject anchors and spawn spots, and slope and vertex-height things. Moving, adding or removing monsters, items, decorations or player starts keeps the match, so testing from the current position still uses the bake. Any other change breaks it, including a moved light or a changed texture.

A practical loop: build and light the map, bake, test, adjust the lights, bake again. Bake last before the final save.

Other cases:

  • Reopening a saved baked map: the map's own nodes and LIGHTMAP count as its bake, so the lump is kept through saves that change nothing, edits that are undone, testing from the current position and the Nodes Viewer's Rebuild nodes button. Any other edit drops it, so bake again. A map restored from a crash backup doesn't get this.
  • Autosave: never contains the lightmap. The next real save writes a bake that still matches.
  • Bake discarded: closing the map, opening another map, or changing the game configuration discards a bake that was not saved.

Seeing the result

Visual mode previews the bake that the next save would write: walls, floors, ceilings and 3D floors get the baked light added to their sector light, as in UZDoom, and the lightmap light things stop drawing as dynamic lights while it shows. The status bar says when the preview turns on and why it is off. Any edit turns it off at once; about half a second after the map stops changing, the editor checks it against the bake again, so undoing the edit brings the preview back. View > Lightmap preview (Visual mode) turns it on or off.

The preview does not light things and sprites from the bake (UZDoom uses the bake's light probes for them), so things near a lightmap light look darker than in the game. Vavoom-style 3D floors preview the way UZDoom draws them: the baker treats every 3D floor as the standard type, so it lights the wrong side of a Vavoom floor's surfaces, and UZDoom and the preview both show that light as baked.

Use Test Map to see the bake in the engine. When the saved test map contains a LIGHTMAP lump, the editor adds the configuration's -enablelightmaps parameter to the engine command line, so make sure the test engine is UZDoom. When you start the map yourself, add -enablelightmaps; without it UZDoom ignores the lump.

When Test Map would run without a bake the map no longer matches, the editor says so before the engine starts. The first time it asks: Yes bakes again and then tests, No tests without the lightmap, Cancel doesn't test. When the map can't be baked in the current configuration, the choice is only OK (test without) or Cancel. After that, each test without the bake shows a warning in the status bar, until the map matches a bake again.

Troubleshooting

Symptom Cause
No Bake Lightmaps menu item The game configuration is not a UZDoom UDMF configuration.
Bake disabled, "Lightmap baking needs a UDMF map." The map is in Doom or Hexen format.
Bake disabled, "No ZDRay executable is set." or "The ZDRay executable was not found" Set the ZDRay executable path in the bake window.
"Bake failed: the bake lit no surfaces" No Lightmap Point Light or Lightmap Spotlight things, or a ZDRayInfo sun that cannot reach any sky surface.
The saved file has no LIGHTMAP lump, with a warning in Errors and Warnings The geometry, a texture, a light or another thing the baker reads changed after the bake.
Testing shows flat sector lighting, with no warning The test engine is not UZDoom. (A test without a bake that no longer matches always warns.)
Your own UZDoom launch shows no baked light The -enablelightmaps parameter is missing.

The baker's command line and the result are written to the editor's log file ("Running lightmap baker:", "Lightmap bake done:", "Removed the baked LIGHTMAP").
