Things Filters Window

With the Things Filters dialog window, you can set up your own Things filters that you can use to show only relevant things in the editor. You can access this dialog from the View menu. Select a filter on the left to edit it, or click on New Filter to create a new one. You can remove the selected filter by clicking on the Delete Selected button. On the right is the Filter Settings are where you can edit the selected filter.

Enter the name of your filter in the Name field. Filter names are unique: a name another filter already has gets a number added, like Monsters (2). If you want to show only Things from a specific category, select the category in the Filter by category box on the Properties tab. Tick Include subcategories to also show Things from the categories inside it (new filters have it ticked). On the Flags tab you can select the settings by which you want to filter the Things (Filter by settings). A grayed/filled checkbox means it is not used for the filter. If the checkbox is empty, it means that the setting may not be set on the Things to pass the filter. If the checkbox is checked, it means that the setting must be set on the Things to pass the filter.

Things Filters are stored separately for each Game Configuration.

Rules

The Rules tab holds a list of rules for what the other tabs can't express: lists and ranges of numbers, comparisons, either-or conditions, name matching and other filters. Click Add rule, then pick the rule's Subject, Key, Operator and Value in the row below the list. Move up and Move down change the order the rules are listed in; they don't change the result.

Match: All rules shows a Thing only when every rule passes; Match: Any rule shows it when at least one rule passes. A Thing is shown when it passes the other tabs and the rule list. Invert is applied last, to that combined result.

Numbers and ranges are written like 3001-3006, 9. For negative numbers use .. between the ends of a range, like -10..-1.

Rules that don't apply. A rule about something the map format doesn't have (Tag, Action, Argument and UDMF field rules in a Doom-format map, Z height without Thing heights, or a flag the game configuration doesn't define) is shown grayed and skipped: the list is decided by the other rules, and a list with only skipped rules passes every Thing. The rule stays in the filter for maps where it applies.

Broken rules. A rule whose value doesn't make sense, that names a filter which doesn't exist, or whose filters refer to each other in a loop, is shown in red with the reason below the list, and the filter gets a warning icon. A broken rule never passes, so with Invert it shows Things, and with Any rule the other rules still decide. If two filters share a name from an older version, a Matches filter rule uses the first one in the list.

Renaming a filter updates the Matches filter rules that use it. Deleting a filter that other filters use asks first.

The rule list and the subcategory option are saved with the filters in the program's settings. The original Ultimate Doom Builder doesn't know about them, and if it saves the same settings file they are lost from it.
