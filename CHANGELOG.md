# Changelog

Changes this fork makes on top of upstream [UltimateDoomBuilder/UltimateDoomBuilder](https://github.com/UltimateDoomBuilder/UltimateDoomBuilder) `master`, which it tracks. The license is unchanged (GPL-3, see `LICENSE.txt`).

## Differences from upstream

- **Linux build and launch:** `make linux` builds the editor and its native library, and `builder.sh` runs it from the checkout or from `Build/`.
- **Fork builds:** pushes check Windows x64/x86 builds and x64 tests; the manual Fork Build workflow publishes portable Windows zips and a Mono-bundling Linux AppImage as `R<upstream>-fork.<commits>`. Release builds show that label and disable upstream updates.
- **Linux node builder:** the bundled zdbsp is rebuilt from the ZDBSP 1.19 source release (Release build, zlib linked statically), so it runs on glibc 2.34 instead of 2.38.
- **Crash handling:** crash dialogs that work on Mono, a map backup before the dialog, worker and timer exceptions reported instead of killing the editor, and the previous log kept as `UDBuilder.log.1`.
- **Responsiveness on Mono:** no more UI deadlocks from blocking invokes, Map Analysis no longer freezes on large result counts, models load on the UI thread, and Visual Mode stops redrawing behind edit dialogs after a texture browser was opened from one, while edit dialogs still update the 3D view on each change, and in Visual Mode the info panel for the targeted line, sector or thing fills in at once, texture thumbnails and their borders included.
- **Mono UI fixes:** blank button text (font remap), Map Analysis and help panels, Mode menu rows, the About dialog, side panel (docker) pages, the unsaved-map title marker, Preferences slider steps, resource-warning resizing in map/configuration dialogs, the texture browser list re-laid out when a stale window size leaves it smaller than its panel, and checkboxes whose value differs across a selection drawn as a filled square instead of a gray check that looked almost like checked.
- **Dark interface theme (Linux):** Preferences > Interface > Interface theme switches menus, toolbars, side panels, info panels, dialogs and the script editor to dark colors after a restart. Its default, System, starts light or dark to match the desktop's theme (checked at startup); a theme already set to Light or Dark stays as chosen. The map view keeps its own colors, floating tool panels such as Map Analysis keep a blue title bar, and the Windows build stays light for now.
- **Help on Linux:** F1 and the Help menu open the matching page of the HTML manual in the default browser, since Mono has no CHM viewer. Set `MONO_HELP_VIEWER` to keep using a CHM viewer. In the AppImage the running editor serves the pages on a local port, so they also open in snap and flatpak browsers (`UDB_HELP_SERVER=1` or `0` forces this on or off). The HTML manual adds pages for Automap mode, Reject Explorer mode and lightmap baking, its sidebar search finds them and Blockmap Explorer mode, and the Features page no longer links to missing pages.
- **Native file dialogs on Linux:** file and folder pickers use the GTK chooser through `zenity` when it is installed, falling back to Mono's dialogs. Ctrl and Shift no longer stay held after a chooser opened by a shortcut closes.
- **Map save safety:** maps are saved to a sibling file and swapped in, backups are written atomically, read-only targets are reported, and UDMF text round-trips as Latin-1.
- **Baked lightmaps:** UDMF maps that carry a baked `LIGHTMAP` lump (ZDRay, for UZDoom's `-enablelightmaps`) open in the editor and keep the lump through saves that don't change the map, edits that are undone, Test from current position and a Nodes Viewer nodes rebuild. Any other edit drops it with a warning, since a bake only matches the nodes it was made with. In the UZDoom UDMF configurations, Tools > Bake Lightmaps runs a ZDRay executable you point it at, with progress and cancel; Save and Test then write the bake (its nodes and lightmap) for as long as the map's geometry and the things the baker reads (lights, polyobject spots and slope things) are unchanged, so moving, adding or removing monsters, items or player starts keeps it, and Test adds `-enablelightmaps`. The ZDRayInfo thing offers `lm_bounce`, a bounce count for indirect light, and sidedefs and sector floors and ceilings offer surface light fields (`lm_lightcolor`, `lm_lightintensity`, `lm_lightdistance` and their `floor`/`ceiling` forms) that make them glow, both read by ZDRay builds that support them. When Test would run without a bake the map no longer matches, it warns, and the first time offers to rebake before testing. Visual mode previews the bake: walls and floors get the baked light added the way UZDoom adds it, and the baked light things stop drawing as dynamic lights. An edit turns the preview off until the map matches the bake again (an undo brings it back after a moment), the status bar says why, and View > Lightmap preview (Visual mode) turns it off. Things and sprites are not lit from the bake. Vavoom-style 3D floors preview the way UZDoom draws them: the baker treats them as the standard type, so their baked light can fall on the wrong side of their surfaces in the game and in the preview alike.
- **Script compilation:** ACS recompiles on Save Map after a script editor save, a failed compile warns and keeps the map marked unsaved, and BCS compiles with the system zt-bcc.
- **Parsers:** DECORATE `Goto` and state-end fixes, UTF-8 BOMs, correct line numbers on LF files, TEXTURES numeric `Blend` under Zandronum configs, and SNDINFO/TERRAIN conditional blocks.
- **Game configurations:** `forceheight`/`forcewidth` thing properties (documented in Help), Zandronum configs targeting Zandronum 3.3 with supported sector-portal choices, engine archive checks (`requiredarchives`), GZDoom/UZDoom `filter/` folders, and DnD (Death and Decay) configurations built on the Zandronum 3.3 configuration.
- **Editing:** arg0str survives bulk edits, the Undo panel previews on single click, a discarded redo branch stays restorable, draw tools withdraw a failed draw cleanly, pasting from another program's clipboard no longer hangs, and saving a prefab no longer marks an unchanged map changed.
- **Clipboard history:** a bounded, in-memory side panel reuses copied or cut geometry across maps without replacing the system clipboard, with duplicate detection, Paste Special and per-entry actions.
- **Texture history:** a recent-texture docker and bindable key/mouse palette reuse textures and flats, set the texture brush, and apply picks to selected or captured surfaces with one undo step.
- **Texture selection:** fuzzy and bounded regex search, size and color sorting, color/transparency filters, and per-configuration pinned favorites with Ctrl+D, context-menu pinning, and favorites-only browsing.
- **Key bindings:** each action accepts a primary and an alternate shortcut in Preferences > Controls, with conflicts checked across both and both shown in the command palette and shortcut reference.
- **Menu bar coverage:** toolbar-only controls have menu items too. View gets Things Filter, Linedef Color Presets and a Side Panels list that opens a panel's tab; Tools gets Test Map Options. Mode toggles (selection numbering, tags and effects, marquee touching, pinned texture offsets), Edit Selection's flip and rotate buttons and the gradient tools appear in Edit, View, Linedefs and Sectors. The draw, curve and extrude options, 3D floor and slope tools, Automap and Visplane Explorer options get their own menu while their mode is on. Menu and toolbar toggles stay in step.
- **Tag ranges:** row/column ordering, start corners, row strides, linedef orientation filtering, and linedef/thing argument targets, with a preview summary and one undo step.
- **Edit Selection:** new toolbar and side panel buttons, and assignable actions with no default key, rotate the selection (including a paste) 90 degrees clockwise or counterclockwise about its center. The 5-degree Rotate Clockwise and Rotate Counterclockwise actions now turn the selection the way their names say on screen, as they already did for things.
- **2D cursor:** a point placed on the map at the mouse (snapped to a vertex or the grid) or at the selection center, saved per map and drawn as a small ring. With Edit Selection's "Around 2D cursor" box checked, rotations turn the selection around it and flips mirror it across its vertical or horizontal line. Scripts read and set it as `UDB.Map.cursor2D`. Its actions have no default key; two are in the Edit menu. Draw Lines mode's "Mirror left/right" and "Mirror up/down" buttons mirror a drawing across the cursor's vertical or horizontal line, with a live preview, in the same undo step; a half drawn from the line back to it closes into one symmetric sector. Draw Lines' "Radial symmetry" button repeats a drawing in 2 to 64 evenly rotated copies around the cursor, joined where they meet, with the same preview and single undo step.
- **Draw Grid:** the post-draw sector dialog edits every split cell, including triangulated grids, without editing an enclosing pre-existing room.
- **Extrude Linedefs:** a new Linedefs-mode tool pulls selected linedef chains out along their normals into new sectors, following the mouse live or taking a typed distance; open chains can also move off-axis on the grid, and loops extruded inward get the height change on their new bands.
- **Terrain scripts:** two UDBScript examples rework existing sectors for vertex-height terrain. Fan Sectors splits a sector into triangles sharing one corner (the best corner, the first valid one, or the one nearest the mouse when run from a script slot hotkey). Subdivide Quad Sectors splits a convex four-cornered sector into a grid of quads or triangles and, in UDMF, blends corner vertex heights onto the new vertices. Both reject sectors with holes, self-intersecting outlines or Plane_Align and Plane_Copy lines, and Subdivide asks before it would flatten a neighbouring vertex-height triangle.
- **Dialog loading:** cached font names and batched list fills make repeated Preferences and Game Configurations opens faster.
- **Help panel modifier reminders:** holding Ctrl, Alt, Shift or a combination for half a second swaps the Help panel to what that chord does in the current mode, followed by the bound shortcuts that use it, until the keys are released (`hintsmodifieroverlay = false;` in `UDBuilder.cfg` turns it off). Key names in the Help panel follow shortcut changes without a restart and list alternate keys, and Edit Selection, Bridge, Floor/Ceiling Align, Make Sectors, the vertex/linedef/sector drag modes, Find and Replace and Map Analysis modes gained help text.
- **Visual mode placeholders:** the missing, unknown and still-loading texture placeholders are 64x64 grids labelled MISSING, UNKNOWN and LOADING.
- **Visual mode animation:** ANIMDEFS and ANIMATED texture/flat frames cycle on geometry, including stock default animations, with a persistent View/toolbar toggle. ANIMDEFS warp/warp2 and SMMU swirls use built-in shaders ahead of hardware shaders; Zandronum warp2 uses the UZDoom formula.
- **Visual mode materials:** GLDEFS brightmaps and compatible hardware shaders render on walls, flats and sprites, with dialect-aware shader support, a persistent toggle hidden when no map is open, and plain-texture fallback for failed programs. In GZDoom-family configurations, GLDEFS normal, specular and PBR material layers also render on walls and flats, lit by dynamic lights with UZDoom's specular and PBR light models.
- **Visual mode fog:** coloured fog follows UZDoom's sector/outside/level density precedence and light-level fallback; MAPINFO lightmode 8/16 use the unset mode, while invalid values warn. Where a fogged sector meets an unfogged one, the fog now covers what lies behind it as in the game instead of brightening it.
- **Visual mode lighting:** under UZDoom configurations, sector light follows the map's UZDoom light mode per pixel, with the software and hardware darkening over distance and black distance fog, which the fog toggle also switches. In every configuration, wall glow is added after the light, things standing in a floor glow brighten as in UZDoom, and fog rendering is on by default.
- **Visual mode models:** OBJ triangle winding matches UZDoom, so translucent models show the correct faces.
- **Resource loading:** faster PK3 file lookups, a PK3 image that fails to read is marked failed instead of breaking the background loader, and required-archive checks can read embedded WADs before a map is open.
- **Resource reload:** unchanged WAD and PK3 readers retain their raw indexes while configuration, parser and image state rebuilds; thing sprite frames resolve through a prefix index and texture sets match exact and prefix filters without a regex, so loads and reloads with many actors or large texture sets are faster; stage timings expose remaining reload costs.
- **Diagnostics:** set `UDB_GEOMETRY_LOG=1` to log texture browser window geometry and resource-warning resize bounds, `UDB_UI_TIMING=1` for dialog-open phases, `UDB_DOCKER_TRACE=1` to trace side panel state, or `UDB_INTERACTION_LOG=1` for interaction timings and marks.

## Experimental

Still being tested: the crash handler rework, the Mono UI action queue, side panel page fixes, the zenity file chooser, the texture browser list re-layout, Extrude Linedefs, the undo branch, clipboard paste/history, texture history/palette and texture selection controls, incremental reload, visual texture animation/materials, Visual mode lighting, the DnD configurations, and `forceheight`/`forcewidth`.

## Linux requirements beyond upstream's

- BCS scripts need zt-bcc installed as `/usr/bin/bcc`.
- The bundled Linux zdbsp node builder needs glibc 2.34 or newer.
